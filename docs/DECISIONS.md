# 분석·설계 의사결정 기록 (면접 대비)

각 단계는 **무엇을 했는가 → 왜 그렇게 판단했는가 → 대안은 무엇이었나** 순서로 적는다.

---

## Step 1. 데이터 이해 (Profiling)

**한 일**: 정제 규칙을 만들기 전에 결측, 형식, 범위, 논리 일관성, 중복, 범주값 종류를 먼저 점검했다.

| 점검 | 결과 | 판단 |
|---|---|---|
| 결측 / 숫자 아님 / 0 이하 | 0건 | 조치 불필요 |
| 날짜 변환 | 실패 0건, 2022-08-05 ~ 2023-11-15 | 형식을 명시하면 안전 |
| 수량 x 단가 = 총액 | 불일치 0건 | 금액 컬럼 신뢰 가능 |
| 완전 동일 행 | 40건 | 삭제 여부 판단 필요 (아래) |
| 제품명 고유값 | 94개 | 표준화 필요 (핵심 문제) |

**왜 이렇게 했나**: 정제 규칙은 "데이터에서 확인된 문제"에만 근거해야 한다. 문제가
없는 컬럼까지 손대면 원본을 왜곡할 위험만 커진다. MES에서 추출한 데이터도 같은
순서(프로파일링 → 규칙 수립)로 다루겠다.

## Step 2. 정제 규칙과 판단 근거

1. **날짜: `format="%d/%m/%Y"` 명시.** 원본은 `05/08/2022`(DD/MM/YYYY). 형식을 생략하면
   `MM/DD`로 해석돼 8월 5일이 5월 8일이 된다. 오류 없이 조용히 틀리는 종류라
   가장 위험하다. → ISO(`YYYY-MM-DD`)로 저장해 SQL 날짜 함수와 정렬이 바로 동작하게 했다.
2. **제품명 94개 → 제품군 11개 + Other.** `Dupleks310`, `Duplex310`, `DUPLEKS310`은 같은
   제품이다. 표준화하지 않으면 "제품별 매출"이 조각나서 순위가 왜곡된다.
   - 원본명은 `product_raw`에 보존하고 표준값은 `product_family`에 따로 둔다 (추적 가능성).
   - `Craft` + `Foodpak`처럼 키워드가 겹치면 소재(Craft)를 우선한다. 우선순위는 규칙 순서로 명시.
   - 회사명(`PTSARIINDAH` 등)은 제품이 아니지만 삭제하지 않고 `Other`로 분류했다 (0.9%, 10건).
3. **중복 40건: 삭제하지 않고 `is_dup_candidate`로 표시.** 원본에 주문번호가 없어서 같은 날
   같은 수량·단가의 주문이 진짜 중복인지, 같은 고객의 별개 주문인지 구분할 수 없다.
   근거 없이 지우면 매출이 과소 집계된다. 판단은 분석 시점에 하고, 지금은 정보를 남긴다.
4. **두 계층 저장 (`raw_sales` → `sales`).** 정제 로직이 틀렸을 때 원본에서 다시 만들 수
   있다. 이번 작업에서 실제로 그런 일이 있었다 (아래 회고).

## Step 2-1. 검증 (Validation)

`src/validate.py`가 적재 후 원본과 DB를 대조한다: 행 수 일치, 매출 합계 일치,
`수량 x 단가 = 매출`, 필수값 NULL 없음, 날짜 범위, ID 유일성.

### 회고: 검증이 통과했는데 버그가 있었다
첫 실행에서 검증은 전부 PASS였지만 `Other`가 99건(9%)이었다. 원인은 정규식 오류였다:
`GreaseProof`와 `Duplex`가 분류되지 않았다. **행 수·합계 검증은 "데이터가 안 사라졌다"만
보장하고 "제대로 분류됐다"는 보장하지 않는다.** 그래서 분류 결과 분포를 눈으로 확인했고,
미분류 목록을 열어보고서야 발견했다. 수정 후 `Other`는 10건이 됐다.
→ 교훈: 검증은 두 종류가 필요하다. (1) 무결성(건수·합계), (2) 의미 정확성(분포·표본 확인).

## 예상 면접 질문

- **Q. 중복을 왜 안 지웠나?** 주문번호가 없어 중복 여부를 판별할 근거가 없었다. 지우면 매출이 줄 수 있어 표시만 했다.
- **Q. 데이터 품질을 어떻게 검증했나?** 원본-DB 건수·합계 대조, 산식 검증, 분류 결과 분포 확인. 분포 확인에서 정규식 버그를 찾았다.
- **Q. 원본을 왜 따로 저장했나?** 정제 규칙이 바뀌거나 틀렸을 때 재처리하기 위해서다.
- **Q. MES 데이터에도 적용할 수 있나?** 같은 순서로 하겠다: 프로파일링, 규칙 수립, 원본 보존, 적재 후 검증.
